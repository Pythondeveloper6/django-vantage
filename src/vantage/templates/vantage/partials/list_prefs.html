{% load static vantage i18n %}{% comment %} The per-list customisation rail. Six independent forms, one per section, each a plain POST. No JavaScript is involved and none is required: every control is a checkbox, a number box or a select, and the page it posts to answers with a redirect back to the list. The script loaded at the bottom adds reordering buttons and a select-all, and nothing else — take it away and the rail still does everything it claims to. Six forms rather than one, for the same reason `vantage/settings.html` uses one form and six reset *buttons*: a form cannot nest, and each section here has its own reset and its own scope. Saving the columns must not also rewrite the filters with whatever happened to be on screen, and separate forms make that structural rather than something the view has to remember. Ordering without JavaScript is a number box per row. Unattractive, and the only thing that works with scripting off; the enhancement script hides them behind ↑/↓ buttons. {% endcomment %}
