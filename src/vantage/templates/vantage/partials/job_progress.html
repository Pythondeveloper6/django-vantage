{% load vantage %} {% comment %} One job's progress, rendered server-side and then kept up to date by polling. Server-rendered first, always. A job that has already finished by the time the page loads — which is every job on a project with no worker — is correct here before a single line of JavaScript runs, and stays correct if none ever does. The polling contract is three data attributes and nothing else: * ``data-job-poll`` the status endpoint, present only while there is something to watch. A finished job carries no URL, so the script cannot start a timer on it however hard it tries. * ``data-job-fill`` the element whose width follows the percentage, via a custom property rather than a style string. * ``data-job-counts`` the sentence, replaced wholesale. The bar is a real ``role="progressbar"`` with ``aria-valuenow``, and the counts are in a live region: a screen-reader user gets the same "38,000 of 40,000" a sighted one does, without the bar itself chattering on every tick. {% endcomment %}
